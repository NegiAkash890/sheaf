Privacy policy

Sheaf is built so that there is nothing to collect.

  • Your files stay on your Mac. Reading, embedding, summarising, searching and organising all happen locally. File contents, names and metadata are never sent anywhere.
  • Network use. Sheaf connects only to the model server on your own machine (127.0.0.1:11434), with one exception that you start yourself: if you choose Install Ollama in setup, Sheaf downloads Ollama once from its official release page on GitHub (github.com/ollama/ollama), checks it against the checksum published there, and keeps it in its own folder. Nothing about you or your files is part of that request. When you choose to download a model, Sheaf asks that local server (Ollama) to fetch it, and Ollama downloads it from its own model library; nothing about your files is part of that request. If a release has in-app updates enabled and you choose to check for updates, it fetches the update feed from the project's release hosting; no identifying information is added.
  • The app has no telemetry, analytics, crash reporting, accounts, advertising or tracking. There is no server operated by the Sheaf project.
  • What is stored. A SQLite database in ~/Library/Application Support/Sheaf holds file paths, extracted text passages, summaries, vectors, relationships, plans and the change journal. Delete that folder to remove it all.
  • The website is static and has no sign-up. Only if you press Yes on the banner, it counts visits and clicks on the download button with Google Analytics, which sets cookies. Press No thanks and nothing is loaded or stored. Your choice is kept in your browser only. Advertising features and personalised ads are switched off. This applies to the website only, never to the app.

Ollama and the models you install are separate software with their own policies.

Verifying the privacy claims

Sheaf says that your files never leave your Mac and that its only network traffic is to the model server on your own machine, apart from the one-time Ollama download you can choose in setup. You do not have to take that on trust. Here are three ways to check.

1. Look at Sheaf's network connections

Open Sheaf and start it reading a folder. In Terminal run:

lsof -nP -i | grep -i sheaf

You should see connections only to 127.0.0.1 (port 11434, the Ollama server on your Mac). Any other address would be a problem; if you see one, please open an issue. The one expected exception is github.com, only while or just after you choose Install Ollama in setup.

2. Block everything but your own machine

Use a firewall such as LuLu (free) or Little Snitch. Deny Sheaf all connections except to 127.0.0.1. Sheaf should keep working normally.

3. Go offline

Install Ollama and the two models first, then turn Wi-Fi off and use Sheaf. Reading, search and organising should all work.

What is not covered

  • Ollama and the models are separate software with their own behaviour and policies. Ollama contacts its own library when you download a model.
  • Downloading Ollama, a model or a Sheaf release needs a connection by nature.
  • Install Ollama in setup downloads Ollama (about 185 MB) from github.com/ollama/ollama once, after you click it. Sheaf checks it against the SHA-256 checksum published with the release, which catches a damaged download, and checks that it is signed with Ollama's Apple developer ID (team 3MU9H2V9Y9), which shows it really is from Ollama. If you would rather not use it, install Ollama yourself (ollama.com or brew install ollama) and Sheaf will use that.
  • If a release enables in-app updates and you choose to check for updates, Sheaf fetches the update feed from the project's release hosting. No identifying information is added.
