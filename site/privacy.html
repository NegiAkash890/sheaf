Privacy policy

Sheaf is built so that there is nothing to collect.

  • Your files stay on your Mac. Reading, embedding, summarising, searching and organising all happen locally. File contents, names and metadata are never sent anywhere.
  • Network use. Sheaf connects only to the model server on your own machine (127.0.0.1:11434). When you choose to download a model, Sheaf asks that local server (Ollama) to fetch it, and Ollama downloads it from its own model library; nothing about your files is part of that request. If a release has in-app updates enabled and you choose to check for updates, it fetches the update feed from the project's release hosting; no identifying information is added.
  • No telemetry, analytics, crash reporting, accounts, advertising or tracking. There is no server operated by the Sheaf project.
  • What is stored. A SQLite database in ~/Library/Application Support/Sheaf holds file paths, extracted text passages, summaries, vectors, relationships, plans and the change journal. Delete that folder to remove it all.
  • The website is static, sets no cookies and has no sign-up.

Ollama and the models you install are separate software with their own policies.

Verifying the privacy claims

Sheaf says that your files never leave your Mac and that its only network traffic is to the model server on your own machine. You do not have to take that on trust. Here are three ways to check.

1. Look at Sheaf's network connections

Open Sheaf and start it reading a folder. In Terminal run:

lsof -nP -i | grep -i sheaf

You should see connections only to 127.0.0.1 (port 11434, the Ollama server on your Mac). Any other address would be a problem; if you see one, please open an issue.

2. Block everything but your own machine

Use a firewall such as LuLu (free) or Little Snitch. Deny Sheaf all connections except to 127.0.0.1. Sheaf should keep working normally.

3. Go offline

Install Ollama and the two models first, then turn Wi-Fi off and use Sheaf. Reading, search and organising should all work.

What is not covered

  • Ollama and the models are separate software with their own behaviour and policies. Ollama contacts its own library when you download a model.
  • Downloading Ollama, a model or a Sheaf release needs a connection by nature.
  • If a release enables in-app updates and you choose to check for updates, Sheaf fetches the update feed from the project's release hosting. No identifying information is added.
